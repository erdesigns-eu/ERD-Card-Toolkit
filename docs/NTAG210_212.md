# NTAG210 and NTAG212

Explicit `ttmNtag210` and `ttmNtag212` profiles are appended to TType2TagModel,
preserving the six previous enum ordinals. Geometry and protocol are based on
[NXP NTAG210/212 data sheet Rev. 3.0, 14 March 2013](https://www.nxp.com/docs/en/data-sheet/NTAG210_212.pdf),
sections 8.5, 8.5.7, 8.6 and the READ/FAST_READ/WRITE/PWD_AUTH commands.

| Model | Total pages | User pages/bytes | Dynamic lock | CFG0 / CFG1 / PWD / PACK |
| --- | --- | --- | --- | --- |
| NTAG210 | 20 | 4..15 / 48 | None | 16 / 17 / 18 / 19 |
| NTAG212 | 41 | 4..35 / 128 | 36 | 37 / 38 / 39 / 40 |

The ordinary PC/SC storage component reads pages/user memory and writes only four-
byte user pages. These writes provide reader status, not independent read-back.
The ACR122 raw component authenticates once with supplied four-byte PWD and exact
two-byte PACK, then reads a page/full user memory or writes/verifies a page in the
retained RF session. It does not change passwords, lock bits or authentication
limits. AUTHLIM can consume a finite attempt budget; no guessing/retries.

Public Type 2 NDEF uses the existing guarded CC/TLV mapping and independent full
read-back. NTAG210 does not read CFG0 as a dynamic lock page. NTAG212 checks its
real dynamic lock page. Both check AUTH0 at the correct CFG0 page and refuse
public NDEF writes when MIRROR_PAGE > 3; their UID ASCII mirror enable mechanism
is different from NTAG213/215/216's MIRROR_CONF bits. Raw memory represents reader-
visible bytes; password access does not imply underlying EEPROM/mirror authenticity.

Type2Demo, Twn4Demo and SmartCardDemo expose the added explicit model choices.
Readers still must implement the chosen transport/profile; model selection is
not physical detection. No signature authenticity, counter programming, password
updates or lock/fuse operations are added by these profiles.
