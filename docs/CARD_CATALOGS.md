# ATR hints and EMV tag descriptions

`ERD.Card.ATR.Catalog` and `ERD.Card.EMV.Tags` add hardware-free diagnostics to the
existing strict ATR and BER-TLV codecs. They perform no reader I/O or automatic
card-profile selection. All public declarations have Delphi XML documentation.
The existing `ERDCardCore` and `ERDCardEMV` runtime packages include these units.

## ATR catalog

`CreateDefaultAtrCatalog` returns an owned immutable `TAtrCatalog`; caller must
`Free`. `FindMatches` first validates the complete ATR, including required TCK,
then returns **all** exact/masked matches in catalog order. Unknown valid ATRs
produce an empty array; malformed ATRs raise before any hint is returned.

The default catalog has nine exact ACS reader-reported entries, one masked
ISO 15693 family rule, and **1,316 valid original CardStudio reports** (582
distinct historical fingerprints). Fourteen malformed original reports have been
removed from runtime data. `CreateDefaultAtrCatalog(False)` selects only the ten
protocol entries. Exact entries cover generic ISO 15693, My-D Vicinity, ST LRI,
I-Code SLI, shared SLIX/SLIX2, shared Classic 1K/4K emulations, Ultralight and EV1.
The family rule masks the card-name bytes and checksum while the separate strict
ATR decoder still verifies the actual checksum. A shared SLIX fingerprint returns
both a model hint and the family hint. It does not distinguish SLIX from SLIX2.

Classic ATRs are also shared by Plus SL1 and SmartMX emulations. Labels state these
ambiguities rather than guessing issuer, country or a specific underlying chip.
ATRs can be generated by a reader or emulated; matching does not authenticate a
card, prove read/write support or establish payment capability. Historical reports use `ahkHistoricalReport` and retain Scheme, CardType,
Country, Issuer and Category metadata. They are explicitly source-attributed
observations. All matches are returned, including conflicting issuer/country
reports; their labels are not a verified identity or a supported-card claim.

```pascal
uses ERD.Card.ATR.Catalog;

Catalog := CreateDefaultAtrCatalog;
try
  Hints := Catalog.FindMatches(AtrBytes);
  // Each hint has Id, Description, Kind and Source; more than one can match.
finally
  Catalog.Free;
end;
```

Applications can construct `TAtrCatalog.Create(Entries)` with their own attributed
entries. Patterns match the entire ATR length and compare `(input and Mask)` with
`Pattern`. Insignificant pattern bits must be zero. Catalog count is bounded to
4096; patterns are 2..33 bytes, masks have equal length and at least one significant
bit. IDs must be unique and descriptions/provenance are required and bounded.
Construction copies all pattern/mask buffers; lookup returns independent metadata.
The catalog has no mutation API and supports concurrent read-only lookup.

## EMV tag metadata

`TEmvTagCatalog.TryDescribe(Tag, Description)` looks up 46 curated **EMV 4.4 Book 3**
identifiers. The identifier is the encoded tag as an integer, for example `$9F26`.
The description includes name, representation, length metadata, a sensitive-data
hint and source. Unknown/private tags return `False` and a cleared record;
issuer-specific meanings are not invented.

```pascal
uses ERD.Card.EMV.Tags;

if TEmvTagCatalog.TryDescribe($9F38, Description) then
  // PDOL: tag/length-only data-object list, not a BER-TLV value stream.
```

The catalog distinguishes constructed templates, binary/packed numeric/text
values, DOLs and packed Track 2 equivalent data. Tag 57 is not a physical magnetic
track frame. A known cryptogram or CVM name does not implement cryptogram generation,
PIN handling or payment authorization. Lengths are diagnostic metadata; context,
format, padding and issuer semantics still belong to actual codecs/protocols.
Minus one denotes a variable maximum not specified by the catalog. The sensitivity
flag is advisory; `False` is not permission to log data or proof it is nonpersonal.
Lookup does not alter the existing EMV reader or validate arbitrary BER identifiers.

## Console and validation

```text
InspectCardTools --help
InspectCardTools --atr 3B8F8001804F0CA0000003060B00350000000056
InspectCardTools --atr 3B00
InspectCardTools --tag 9F26
InspectCardTools --tag DF0101
```

The console prints descriptions/provenance, not card payloads. It accepts explicit
bounded inputs, returns unknown for unknown valid data and refuses malformed ATRs.
`CardCatalogs.Tests.dpr` checks exact/family overlap, emulation ambiguity, every bad
TCK, unknown inputs, copied custom buffers, invalid definitions, all 65536 two-byte
lookup identifiers and independently checked EMV field metadata.

Sources are independently transcribed protocol facts:

- [ACS ACR1552U Series Reference Manual 1.09](https://www.acs.com.hk/download-manual/13473/REF-ACR1552U-Series-1.09.pdf),
  section 5.3.8 reported ATR table. SHA-256
  `ab9dc769d8a856913350cc4195b5823587267466f5415e9ddf763356c3f88a6a`.
- [EMV 4.4 Book 3, October 2022, Annex A](https://github.com/mvallim/emv-qrcode/blob/8d8ff6fcaac3cf2905e9e659fb6d4cfc4e43cbed/docs/EMV_v4.4_Book_3_Application_Specification.pdf).
  SHA-256 `06d64d1b85d64a2939b6fd673273f5b8c3a5a37e6931a2488799ccc161c8f8a3`.

No external implementation, PDF or unverified issuer database is bundled as runtime
data. These are curated initial catalogs; additional attributed entries remain
possible. Delphi build and actual Help Insight inspection remain separate checks.

## Historical dictionaries and browsing

`TLegacyAtrCatalog.GetReports` exposes only the 1,316 valid retained reports;
`SourceRow` preserves the one-based row from the original 1,330-row source.
No source ATR is repaired or has its checksum silently recalculated. The retained
original file under `reference/legacy` remains unchanged archival evidence.

`TEmvTagCatalog.TryDescribe` retains the 46 curated Book 3 descriptions.
`FindDescriptions` returns that description first, then all matching historical
labels from the original 515-entry inventory. Historical representations are
`eteUnknown`, length is unspecified and sensitivity is conservative. Parent-path
and private-tag meanings require issuer context. `TLegacyEmvTagCatalog.FindByPath`
also handles the two original X/Y index patterns; these are valid symbolic nested
paths, not malformed tag identifiers.

`TApduCatalog.GetInstructions` exposes 35 candidate INS meanings; CLA/card context
must still be considered. `GetHistoricalStatuses` exposes 205 valid patterns after
removing eleven malformed placeholders. `FindStatusDescriptions` prepends dynamic
ISO 7816 explanations for 9000, 61xx, 6Cxx and 63Cx, then returns historical
alternatives. A diagnostic explanation never triggers retry, GET RESPONSE or PIN
handling. `61 00` and `6C 00` mean 256 bytes; 63Cx is command-dependent.

`TEmvAidCatalog.GetEntries` exposes 61 valid CardStudio/CardPeek suggestions.
The malformed odd-nibble AID was removed. Five-byte RID suggestions have
`PrefixOnly=True`; they are not exact application instance identifiers. The EMV
reader still uses explicit selection or PSE/PPSE discovery, never automatic
probing through the historical AID list.

`CardCatalogDemo` has its own TForm/DFM. It browses and filters each complete
inventory and performs offline lookup. Its PC/SC selector receives native reader
arrival/removal and card-state events; offered ATR inspection uses the latest
observed snapshot without connecting or transmitting an APDU. `ReaderToolsDemo`
now also shows expanded instruction/status and historical tag explanations.

Pascal sources containing accented names or Unicode punctuation explicitly declare
`{$CODEPAGE UTF8}`. This prevents Delphi from interpreting UTF-8 literals using the
Windows ANSI code page (for example, `Crédit` becoming `CrÃ©dit`). The distribution
validator rejects non-ASCII Pascal sources without a UTF-8 BOM or an early UTF-8
code-page directive. Catalog tests compare the accented issuer and APDU punctuation
against independently specified Unicode code points.
